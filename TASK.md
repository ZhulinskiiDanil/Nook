# Nook — ТЗ

**Nook** — Windows-приложение на Rust, которое держит рабочий стол чистым и не рисует поверх обоев ни одной рамки. Порядок задают углы экрана. Что куда положить, решает Claude Code через MCP-мост. Nook показывает превью, исполняет план и умеет всё откатить.

Макет: `docs/wireframe.svg` (кадр 1 — сейчас, 2 — после, 3 — превью).
Версия ТЗ: 1.0, 15.10.2026.

---

## 1. Контекст

Сейчас на столе около 62 элементов: две колонки ярлыков слева, россыпь файлов справа (копии, бэкапы, установщики, логи, два `desktop.ini`) и ряд папок внизу по центру — прямо поверх персонажа на обоях. Обои тёмные (звёздное небо), персонаж в центре.

Пользователь хочет **чище**, а не «аккуратнее». Уже отвергнуто:

- рамки, панели, подложки, подписи групп, любые оверлеи поверх стола;
- «спрятать все иконки и вызывать их лаунчером по хоткею».

Решение: на столе остаются только настоящие иконки Windows, примерно 15–20, по углам. Всё остальное разложено по настоящим папкам или отправлено в карантин. Сортирует Claude Code, Nook — его руки и глаза.

## 2. Целевой результат (кадр 2 макета)

| Угол | Группа | Что там | Как выглядит |
|---|---|---|---|
| ↖ | `apps` | ярлыки, которыми реально пользуются (~8) | 2 колонки, **без подписей** |
| ↗ | `projects` | до 5 папок проектов | колонка, одинаковая иконка папки, неактивные — полупрозрачные |
| ↘ | `inbox` | свежие и новые файлы | ряд справа налево; **сюда падает всё новое** |
| ↙ | `trash` | Корзина | одна иконка |

- Отступ от краёв — 1 клетка сетки рабочего стола.
- Центр и низ (персонаж) свободны: раскладка обходит «занятые» области обоев (6.2).
- Поверх стола Nook не рисует ничего. Единственное исключение — превью, и только пока зажата клавиша.
- Углы групп настраиваются в конфиге.

## 3. Пользовательский сценарий

1. Пользователь пишет в Claude Code: «разбери рабочий стол».
2. Claude вызывает `status` → `scan` → `wallpaper_map`, по непонятным элементам — `peek`, затем `propose_plan`.
3. Nook проверяет план; иконка Nook в трее получает точку («план ждёт»).
4. Пользователь зажимает **LCtrl+LAlt** и видит стол «после». Отпустил — всё как было.
5. Двойное нажатие LCtrl+LAlt (или Enter во время превью) — применить. Esc во время превью — отклонить.
6. Правки — словами в Claude Code («blitzkrieg.psd не трогай»). Claude присылает новый план, старый заменяется.
7. После применения всё записано в журнал. Откат — «Отменить последнее» в трее или `undo` через MCP.

## 4. Архитектура

### 4.1 Процессы

Один крейт, два бинарника:

- **`nook.exe`** (subsystem windows) — демон: трей, хоткей, окно превью, наблюдатель за папками, раскладка, исполнение планов, IPC-сервер. Автозапуск через `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Один экземпляр (именованный mutex в `Local\`).
- **`nookctl.exe`** (subsystem console):
  - `mcp` — stdio MCP-сервер. Каждый вызов проксирует в демон по IPC. Если демон не запущен — запускает его и ждёт pipe до 5 с.
  - `doctor`, `dump [--json]`, `layout --dry-run`, `positions save|restore`, `sandbox init`, `apply <plan-id>`, `undo` — для отладки и проверки.

Подключение к Claude Code:

```
claude mcp add --scope user nook -- "C:\path\to\nookctl.exe" mcp
```

### 4.2 IPC

Named pipe `\\.\pipe\nook-<SID пользователя>`, JSON-RPC 2.0, одно сообщение на строку. DACL — только текущий пользователь, `PIPE_REJECT_REMOTE_CLIENTS`.

### 4.3 Потоки

- Главный поток — STA: message loop, COM-вызовы shell (`IFolderView2` и т. д.), low-level keyboard hook, окно превью, трей. Все обращения к виду рабочего стола — только отсюда.
- Tokio-рантайм на отдельном потоке — IPC. Запросы в UI-поток идут через канал + `PostMessage` в скрытое окно.
- Тяжёлое (хеши, миниатюры, обход папок, рендер кадра превью) — рабочие потоки, каждый со своим `CoInitializeEx`.

### 4.4 Хранилище

| Что | Где |
|---|---|
| конфиг | `%APPDATA%\Nook\config.toml` (создаётся с дефолтами, пример — приложение B) |
| состояние, планы, журнал, логи, иконки | `%LOCALAPPDATA%\Nook\` (`state.json`, `plans\`, `journal\`, `logs\`, `icons\`) |
| карантин | `%USERPROFILE%\.nook\quarantine\<plan-id>\` — тот же том, что и Desktop, чтобы перемещение было мгновенным |

Файлы состояния пишутся атомарно (временный файл + rename).

### 4.5 Стек (ориентир; версии — актуальные)

`windows` (Win32/COM), `rmcp` (официальный Rust SDK для MCP), `tokio`, `serde`/`serde_json`, `toml`, `schemars`, `notify`, `blake3`, `encoding_rs`, `zip`, `tracing` + `tracing-appender`, `anyhow`/`thiserror`.

Никаких GUI-фреймворков: превью — чистый Win32 + Direct2D/DirectWrite/WIC.

### 4.6 Модули (ориентир)

```
src/
  bin/nook.rs, bin/nookctl.rs
  config.rs, state.rs, tray.rs
  shell/    desktop_view.rs (IFolderView2, позиции, сетка), items.rs (перечисление, pidl → путь),
            shortcuts.rs (.lnk/.url), thumbs.rs, wallpaper.rs, explorer_settings.rs
  intel/    userassist.rs, taskbar_pins.rs, uninstall.rs, hashing.rs, heuristics.rs, peek.rs
  layout/   busy_map.rs, engine.rs          ← чистая логика, без Win32
  plan/     model.rs, validate.rs, apply.rs, journal.rs, undo.rs, quarantine.rs
  preview/  hotkey.rs, overlay.rs, render.rs
  inbox/    watcher.rs, keeper.rs
  ipc/, mcp/
```

Чистая логика (раскладка, валидация, эвристики, парсеры) не зависит от Win32 и покрывается тестами.

## 5. Данные

### 5.1 Элемент стола (`scan`)

```jsonc
{
  "id": "it_7f3k2q",
  "name": "robot_03 копия 2.png",
  "display_name": "robot_03 копия 2",
  "path": "C:\\Users\\X\\Desktop\\robot_03 копия 2.png",
  "source": "user",              // user | public | virtual
  "kind": "file",                // file | folder | shortcut | url | virtual
  "ext": "png",
  "size": 482113,
  "created": "2026-09-30T12:01:00Z",
  "modified": "2026-09-30T12:01:00Z",
  "attributes": ["archive"],
  "writable": true,
  "cell": { "col": 32, "row": 2 },
  "group": null,                 // apps | projects | inbox | trash | null
  "caption_hidden": false,
  "shortcut": null,              // для .lnk/.url — см. ниже
  "folder": null,                // для папок — см. ниже
  "hints": {
    "duplicate_of": ["it_k2m9aa"],   // тот же blake3
    "same_target_as": [],
    "is_copy": true, "is_backup": false, "is_installer": false, "is_temp": false,
    "age_days": 15
  }
}
```

- `shortcut`: `target`, `args`, `aumid`, `url` (для `.url`), `target_exists`, `pinned_to_taskbar`, `launch_count`, `last_launch`, `uninstall_match` (DisplayName из Uninstall, если нашлось).
- `folder`: `entries`, `top_entries` (до 20 имён), `total_size` (обход с лимитом 2 с), `newest_modified`.

Правила:

- `id` стабилен: из NTFS FileId (`GetFileInformationByHandleEx(FileIdInfo)`: серийный номер тома + 128-битный id; открывать с `FILE_FLAG_BACKUP_SEMANTICS`, минимальными правами и полным share-режимом). Переживает переименование. Для виртуальных элементов — из CLSID.
- Элементы стола — это user Desktop (`FOLDERID_Desktop`, может быть в OneDrive) + Public Desktop (`FOLDERID_PublicDesktop`, запись обычно требует админа → `writable: false`) + виртуальные (Корзина, Этот компьютер).
- `hints` — подсказки, а не решения. Решает Claude.

### 5.2 План (`propose_plan`)

```json
{
  "title": "Первая уборка",
  "layout": {
    "apps":     [{ "item": "it_steam", "pin": { "col": 1, "row": 1 } }, "it_spotify", "it_blender"],
    "projects": ["new:%DESKTOP%\\Dev", "it_bkillustr", "new:%DESKTOP%\\GD"],
    "inbox":    ["it_robot02"],
    "trash":    ["it_recyclebin"]
  },
  "actions": [
    { "op": "move_to_folder", "item": "it_lexpsd", "dest": "%DESKTOP%\\Art", "create_dirs": true,
      "reason": "исходники blitzkrieg" },
    { "op": "quarantine", "item": "it_r03c2", "reason": "копия robot_03.png, тот же хеш" },
    { "op": "hide_caption", "item": "it_steam", "reason": "приложения без подписей" },
    { "op": "dim", "item": "it_learnhtml", "value": true, "reason": "не менялась 5 месяцев" },
    { "op": "folder_icon", "item": "new:%DESKTOP%\\Dev", "icon": "default", "reason": "единый стиль" },
    { "op": "explorer_setting", "key": "hide_protected_os_files", "value": true,
      "reason": "спрятать desktop.ini" }
  ]
}
```

Валидация. План отклоняется целиком, с понятным списком ошибок, если нарушено хоть одно правило:

- **Каждый элемент стола — ровно в одном месте:** в группе `layout` или вне стола (`move_to_folder` / `quarantine`). Неразобранные элементы перечисляются в ошибке.
- Папки, которые план создаёт на столе (`new:`), тоже обязаны попасть в группу.
- Пути назначения — внутри `allowed_roots`. Перезапись запрещена: при конфликте имени добавляется суффикс « (2)».
- Только действия из 5.3, у каждого — непустой `reason`.
- Элементы не изменились с момента `scan` (FileId, размер, mtime). Иначе — ошибка «пересканируй».
- `%DESKTOP%` раскрывается в путь user Desktop.
- Точные клетки считает Nook (раздел 6). Claude может закрепить клетку через `pin` — это редкий случай.

Состояния плана: `pending` → `applied` | `rejected` | `superseded` | `failed`. Новый план заменяет ожидающий (`superseded`).

### 5.3 Действия (whitelist)

| op | Что делает | Ограничения | Откат |
|---|---|---|---|
| `move_to_folder` | переместить в папку (`create_dirs` — создать) | только `writable`, только в `allowed_roots` | вернуть на место |
| `quarantine` | переместить в карантин | **ничего не удаляется** | вернуть |
| `rename` | переименовать | не для виртуальных | вернуть имя |
| `hide_caption` | переименовать ярлык в «невидимое» имя | только `.lnk`/`.url`; уникальность — разной длиной имени; оригинал хранится в `state.json` | вернуть имя |
| `dim` | поставить/снять атрибут Hidden — Explorer рисует иконку полупрозрачной | только если в Explorer включён показ скрытых файлов, иначе элемент исчезнет → ошибка валидации | вернуть атрибут |
| `folder_icon` | `desktop.ini` с `IconResource` + атрибут папки (`PathMakeSystemFolder`) | прежний `desktop.ini` сохраняется в журнал | восстановить |
| `explorer_setting` | `hide_protected_os_files`, `auto_arrange_off`, `hide_this_pc_icon` | только эти ключи | вернуть значения |

Виртуальным элементам доступны только `layout` и `hide_this_pc_icon`.

## 6. Раскладка

### 6.1 Сетка

- Вид рабочего стола: `IShellWindows::FindWindowSW(CSIDL_DESKTOP, SWC_DESKTOP, SWFO_NEEDDISPATCH)` → `IUnknown_QueryService(SID_STopLevelBrowser)` → `IShellBrowser::QueryActiveShellView` → `IFolderView2`. Это известный рецепт Raymond Chen («Manipulating the positions of desktop icons»). **Не** использовать WorkerW/SysListView32-хаки и `LVM_*` с межпроцессной памятью.
- Позиции: `GetItemPosition` / `SelectAndPositionItems(..., SVSI_POSITIONITEM)` — пачкой, чтобы не мигало.
- Шаг сетки — `GetSpacing`, размер иконки — `GetViewModeAndIconSize`. Авто-упорядочивание должно быть выключено (`GetCurrentFolderFlags`, `FWF_AUTOARRANGE`); если включено — в плане нужно действие `auto_arrange_off`.
- Область — рабочая область основного монитора (`rcWork`, без панели задач). Перевод координат: HWND вида через `IShellView` (`IOleWindow::GetWindow`) → `ScreenToClient`.
- Оба процесса — Per-Monitor-V2 DPI aware.
- `doctor` проверяет запись и обратное чтение позиции (round-trip) — только после `positions save`.

### 6.2 Карта занятости обоев

- Обои берутся такими, как они на экране: `IDesktopWallpaper` (`GetWallpaper`, `GetPosition`, `GetMonitorRECT`, `GetBackgroundColor`). Режимы Fill, Fit, Stretch, Center, Tile; Span — после MVP. Если путь недоступен (слайд-шоу, Spotlight) — `%APPDATA%\Microsoft\Windows\Themes\TranscodedWallpaper`.
- Алгоритм: уменьшить → размыть (чтобы звёзды и мелкий шум не считались занятыми) → для каждой клетки посчитать яркость относительно фона и плотность границ → `busy` от 0 до 1. Клетки выше `busy_threshold` не занимаются.
- `wallpaper_map` отдаёт Claude картинку (обои + сетка + занятые клетки + текущие иконки рамками) и матрицу `busy`.

### 6.3 Движок

| Группа | Старт | Заполнение |
|---|---|---|
| `apps` | ↖ + отступ | колонками по `apps_columns` (2), сверху вниз |
| `projects` | ↗ + отступ | колонкой сверху вниз, затем следующая колонка влево |
| `inbox` | ↘ + отступ | рядом справа налево, затем ряд выше |
| `trash` | ↙ + отступ | одна клетка |

- Занятые клетки (`busy`) и клетки других групп пропускаются.
- Движок — чистая детерминированная функция: (сетка, busy, группы, pin) → клетки. Тесты — «золотые» ASCII-сетки.
- `nookctl layout --dry-run` печатает ASCII-сетку.

### 6.4 Хранитель раскладки

- Смена разрешения, монитора или DPI (`WM_DISPLAYCHANGE`, `WM_DPICHANGED`) или обоев (`WM_SETTINGCHANGE` с `SPI_SETDESKWALLPAPER` плюс сравнение пути) → пересчитать busy и раскладку, переставить иконки.
- Если Explorer массово сбросил позиции (больше половины элементов сдвинулось разом) — восстановить. Если пользователь руками передвинул 1–2 иконки — принять как его выбор (pin) и **не воевать**.
- Explorer перезапустился (`TaskbarCreated`, ошибки RPC) — заново получить вид и вернуть иконку в трей.

### 6.5 Входящие

- `notify` следит за user Desktop и Public Desktop.
- Новый элемент (создан или перемещён на стол; финальное переименование из `.crdownload`/`.part`/`.tmp` тоже считается новым) → когда он появится в виде (опрос до 3 с), ставится в следующую свободную клетку `inbox`.
- Переименование на месте позицию не меняет. Игнор-маски — в конфиге.
- Сам Nook ничего не сортирует: он только ставит новое в ↘. Сортирует Claude по запросу.

## 7. Превью (кадр 3 макета)

### 7.1 Клавиши

- Low-level keyboard hook (`WH_KEYBOARD_LL`). В колбэке — минимум работы, сразу `PostMessage`.
- **Показ:** удержание **LCtrl+LAlt** без других клавиш дольше 150 мс при ожидающем плане. Отпускание любой из двух клавиш — мгновенно скрыть.
- **AltGr не должен срабатывать никогда.** У пользователя польская раскладка, а AltGr = фиктивный LCtrl + RAlt. Триггер — только `VK_LCONTROL` + `VK_LMENU`; фиктивный LCtrl, пришедший в паре с RAlt, не считается.
- **Применить:** двойное нажатие LCtrl+LAlt (два цикла «нажал-отпустил» за 400 мс) или Enter во время превью. Работает, только если превью этого плана хотя бы раз показывалось.
- **Отклонить:** Esc во время превью.
- Enter и Esc глотаются хуком, только пока превью на экране.
- Любая другая клавиша при зажатых LCtrl+LAlt (кроме Enter/Esc во время превью) означает чужое сочетание: превью не показывать или скрыть.
- В полноэкранных приложениях и играх (`SHQueryUserNotificationState`: `QUNS_BUSY`, `QUNS_RUNNING_D3D_FULL_SCREEN`, `QUNS_PRESENTATION_MODE`) — не реагировать.
- Без ожидающего плана удержание ничего не делает.
- Сочетания настраиваются в конфиге.

### 7.2 Окно и рендер

- Стили `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST`. Размер — рабочая область основного монитора, панель задач остаётся видна. `UpdateLayeredWindow` с premultiplied 32-bit DIB.
- Рендер: Direct2D (DC render target) + DirectWrite + WIC.
- Кадр собирается заранее, как только план принят; показ — быстрее 100 мс.

### 7.3 Что на кадре

1. Обои как на экране. Они перекрывают реальные иконки и окна — это «подглядывание» на стол.
2. Текущие иконки на старых местах: то, что уедет в папки, — с непрозрачностью 15 %; то, что уйдёт в карантин, — 30 % и тонкий красный контур.
3. Итог — **настоящие иконки** (`IShellItemImageFactory`, размер как на столе; для новых папок — иконка из `folder_icon` или стандартная). Подписи как у Explorer: шрифт из `SPI_GETICONTITLELOGFONT`, белый с тенью, до 2 строк с многоточием. Скрытые подписи — без текста, `dim` — 50 %. Под изменёнными элементами — тонкая акцентная линия (`accent` из конфига).
4. Одна строка сверху по центру, белым с тенью: `62 → 17 · отпусти — как было · Ctrl+Alt дважды — применить`.

Больше на кадре ничего нет: ни панелей, ни списков, ни кнопок.

## 8. MCP-мост

- Сервер `nook`, транспорт stdio (`rmcp`). **stdout — только JSON-RPC**, логи — в файл или stderr.
- Картинки возвращаются как image content (PNG/JPEG в base64), не путями.
- В `instructions` сервера — текст из приложения A.

| Инструмент | Назначение |
|---|---|
| `status` | версия, Windows, монитор, сетка (колонки × ряды, шаг), размер иконок, флаги вида, настройки Explorer, ожидающий и последний план, размер карантина |
| `scan(offset?, limit?)` | элементы стола (5.1), по умолчанию до 200 |
| `peek(id)` | миниатюра до 512 px (картинки, видео, PSD, PDF — через shell); начало текста до 4 КБ (UTF-8/UTF-16/CP1251); содержимое папки или zip (до 50 записей); для exe — `FileDescription`, `ProductName`, `CompanyName` |
| `wallpaper_map(include_icons?)` | картинка обоев с сеткой и занятостью + матрица `busy` |
| `propose_plan(plan)` | проверить и выставить план → `plan_id`, сводка «62 → 17», предупреждения, ошибки |
| `get_plan(id)` | план, состояние, результаты по действиям |
| `wait_for_decision(id, timeout_s?)` | ждать решения пользователя (по умолчанию 60 с, максимум 300); по таймауту — `still_pending` |
| `cancel_plan(id)` | снять ожидающий план |
| `undo(plan_id?)` | откатить последний (или указанный) применённый план |
| `history(limit?)` | применённые планы со сводками |
| `quarantine_list`, `quarantine_restore(ids)` | смотреть карантин и возвращать из него |

- Инструментов удаления и очистки карантина нет. Карантин очищает только пользователь из трея, с подтверждением.
- `apply_plan` через MCP по умолчанию отсутствует и появляется, только если `allow_ai_apply = true`.
- Откуда берутся подсказки в `scan`:
  - `launch_count`, `last_launch` — UserAssist (детали — раздел 13);
  - `pinned_to_taskbar` — сравнение с ярлыками в `%APPDATA%\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar\` по target + args или AppUserModelID;
  - `duplicate_of` — blake3, считается только для файлов одинакового размера;
  - `is_installer` — имя (`setup|install|installer|установ`), `.msi`, версия PE; `uninstall_match` — поиск в `...\CurrentVersion\Uninstall` (HKLM, HKLM\WOW6432Node, HKCU);
  - `is_copy` — « - копия», « копия», « - Copy», «Copy of», « (2)»; `is_backup` — `backup`, `бэкап`, `.bak`; `is_temp` — `.log`, `.tmp`, `~$*`, `.crdownload`, `.part`;
  - `target_exists: false` — битый ярлык.

## 9. Безопасность продукта

- **Nook никогда ничего не удаляет.** Только перемещает — в папки или в карантин.
- Только действия из whitelist, только внутри `allowed_roots`, без перезаписей.
- Журнал с опережающей записью: перед действием пишется намерение, после — результат. Сбой посреди плана → остановиться и откатить выполненную часть.
- Перед применением делается снимок позиций всех иконок. `undo` восстанавливает файлы, имена, атрибуты, `desktop.ini`, настройки Explorer и позиции. Критерий: `scan` после `undo` совпадает со `scan` до `apply` (кроме служебных полей).
- Занятые файлы (открыты в Photoshop и т. п.) пропускаются с предупреждением.
- Перемещение: в пределах тома — `MoveFileExW` без `MOVEFILE_REPLACE_EXISTING`; между томами — `IFileOperation` с `FOF_NO_UI`.
- После файловых операций — `SHChangeNotify` и обновление вида.

## 10. Безопасность разработки (обязательно)

- **Не трогать реальный рабочий стол файловыми операциями, пока пользователь явно не напишет «можно на живом».**
- До этого все файловые операции — только в песочнице: `NOOK_DESKTOP_ROOT=C:\nook-sandbox`. `nookctl sandbox init` читает реальный стол (только чтение!) и создаёт песочницу с теми же именами: файлы до 20 МБ копирует целиком (чтобы работали дубли и превью), большие — заглушками, папки — только заглушками верхнего уровня, ярлыки — копиями. В режиме песочницы позиции иконок не трогаются, сетка фиктивная.
- Позиции иконок реального стола (этап M3) — только после `nookctl positions save` и с предупреждением пользователю.
- Никаких `rm` / `del` / `Remove-Item` по файлам рабочего стола. Никогда.

## 11. Этапы

Каждый этап заканчивается сборкой, тестами, clippy без предупреждений и отчётом.

**M0 — каркас и `doctor`.** Крейт с двумя бинарниками, конфиг с дефолтами, логирование, DPI awareness, mutex одного экземпляра. `nookctl doctor` выводит: сборку Windows, монитор и рабочую область, DPI, шаг сетки, размер иконок, флаги вида (auto-arrange, snap to grid, показ иконок), настройки Explorer (`Hidden`, `ShowSuperHidden`, `HideFileExt`), обои и режим, число элементов по источникам.
*Готово, когда:* на машине пользователя `doctor` показывает правдоподобные данные и около 62 элементов.

**M1 — скан и peek (только чтение).** Всё из 5.1: ярлыки `.lnk`/`.url`, закрепы панели задач, UserAssist, Uninstall, хеши и дубли, эвристики, сводка по папкам, `peek`. Команды `nookctl dump [--json]` и `nookctl sandbox init`.
*Тесты:* парсер UserAssist и ROT13 на фикстурах, декодирование текста, эвристики имён (кириллица), дубли.
*Готово, когда:* в `dump` кириллица отображается правильно, копии `robot_03` найдены по хешу, установщики помечены, ярлыки с панели задач отмечены.

**M2 — демон и MCP (только чтение).** `nook.exe` с минимальным треем (только «Выход»), IPC, `nookctl mcp` с `status`, `scan`, `peek`, `wallpaper_map` и `instructions` из приложения A.
*Готово, когда:* после `claude mcp add` Claude Code получает картинку обоев с сеткой и внятно описывает стол.

**M3 — раскладка.** Карта занятости, движок, `layout --dry-run`, `positions save|restore`, расстановка одних позиций (без файловых операций) по эвристическим группам — для проверки.
*Готово, когда:* dry-run обходит персонажа; `save` → расстановка → `restore` возвращает позиции точно; после перезапуска `explorer.exe` позиции на месте.

**M4 — планы.** Модель, валидация, все действия из 5.3, журнал, карантин, `undo`. MCP: `propose_plan`, `get_plan`, `wait_for_decision`, `cancel_plan`, `undo`, `history`, `quarantine_*`. Применение на этом этапе — через `nookctl apply`.
*Тесты:* неразобранные элементы, пути вне `allowed_roots`, конфликты имён, сбой посреди плана с откатом, `undo` возвращает исходное состояние. Всё — в песочнице.
*Готово, когда:* полный цикл работает в песочнице. Первый прогон на живом столе — только после разрешения пользователя.

**M5 — превью и клавиши.** Хук, удержание, двойное нажатие, Enter/Esc, исключение AltGr, полноэкранный режим, рендер кадра. Трей: точка «план ждёт», подсказка, меню («Отменить последнее», «Пауза входящих», «Открыть карантин», «Открыть конфиг», «Логи», «Выход»).
*Готово, когда:* кадр превью совпадает со столом после применения; AltGr + ą/ę/ł не вызывает превью; в полноэкранной игре превью не появляется.

**M6 — входящие, хранитель, иконки.** Наблюдатель за папками, обработка временных файлов, размещение в ↘, хранитель раскладки, автозапуск, генерация единой иконки папки (`.ico` с размерами 16–256, PNG внутри; цвет — из конфига, после MVP — из палитры обоев).
*Готово, когда:* файл, сохранённый из браузера на стол, через ~1 с стоит в ↘; ручное перетаскивание не откатывается; после смены обоев раскладка пересчитана.

## 12. Критерии приёмки

- Стол после уборки соответствует кадру 2 макета: только иконки Windows по углам, центр и низ свободны, ни одной рамки.
- `scan` видит все элементы (user, Public, виртуальные) с верными именами, клетками и целями ярлыков.
- План с неразобранным элементом отклоняется с понятным списком.
- Превью появляется быстрее 100 мс после порога удержания и исчезает мгновенно; AltGr его не вызывает.
- `undo` возвращает стол к состоянию до плана: файлы, имена, атрибуты, позиции.
- Ничего не удаляется; всё из карантина возвращается.
- Демон в простое: около 0 % CPU, меньше 40 МБ RAM, никаких окон, кроме превью.

## 13. Подводные камни

- Везде W-версии API и UTF-16: на столе кириллица («Семен КС конфиги», «копия»).
- Два `desktop.ini` на столе — от user Desktop и Public Desktop. Это системные файлы: их не перемещать, а прятать настройкой `hide_protected_os_files`.
- Ярлыки из Public Desktop без прав админа не переименовать и не переместить. В MVP — только раскладка (`writable: false`, Claude это учитывает). После MVP — разовая операция с UAC, переносящая выбранные ярлыки в user Desktop.
- Desktop может быть перенаправлен в OneDrive — путь только через `SHGetKnownFolderPath`.
- Вид рабочего стола — только из STA-потока. После перезапуска Explorer интерфейсы становятся недействительными.
- UserAssist: `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist\{GUID}\Count`, GUID `{CEBFF5CD-ACE2-4F4F-9178-9926F41749EA}` (exe) и `{F4E57C4B-2036-45F0-A9AB-443BCFE33D9F}` (ярлыки). Имена закодированы ROT13, в начале могут стоять GUID известных папок. Значение — 72 байта: счётчик запусков — u32 по смещению 4, время последнего запуска — FILETIME по смещению 60. Если отслеживание запусков выключено в настройках приватности, данных нет — это нормально. Парсер должен спокойно переживать мусор.
- `.url` (ярлыки Steam-игр) — это INI: `[InternetShortcut]` и `URL=steam://rungameid/...`.
- Ярлыки Squirrel-приложений (Discord и т. п.) указывают на `Update.exe` с аргументами — сравнивать target вместе с args.
- Обновляторы приложений иногда пересоздают свои ярлыки на столе. Новый ярлык с тем же target, что у ярлыка без подписи, помечается `same_target_as` в `scan` и попадает во входящие.
- Невидимое имя ярлыка — U+2800 или U+00A0 (проверить, что подпись действительно пустая). Windows обрезает пробелы и точки в конце имени.
- `dim` через атрибут Hidden работает, пока в Explorer включён показ скрытых файлов. `doctor` и валидация проверяют `Hidden = 1`.
- `desktop.ini` в папке учитывается, только если у папки атрибут ReadOnly или System (`PathMakeSystemFolder`); у самого `desktop.ini` — Hidden + System. После изменения — `SHChangeNotify(SHCNE_UPDATEITEM)`.
- Настройки Explorer (`Hidden`, `ShowSuperHidden`, `HideDesktopIcons\NewStartPanel`): после записи разослать `WM_SETTINGCHANGE` и обновить вид (`IShellView::Refresh`).
- Windows снимает медленные хуки клавиатуры (`LowLevelHooksTimeout`) — в колбэке никакой работы.

## 14. Не делаем

- Рамки, панели, подложки, подписи групп, виджеты поверх стола.
- Скрытие всех иконок с вызовом лаунчером.
- Собственную логику сортировки или «обучение правилам»: решает Claude Code.
- ИИ внутри приложения, API-ключи, сеть.
- GUI настроек — достаточно `config.toml`.
- Удаление файлов в любом виде.
- Несколько мониторов, Span-обои, цвет иконок из обоев — после MVP.

## Приложение A. Правила уборки (`instructions` MCP-сервера)

```
Ты разбираешь рабочий стол пользователя через Nook. Порядок задают углы:
↖ apps — ярлыки, которыми реально пользуются (до ~10), без подписей (hide_caption);
↗ projects — до 5 папок проектов; неактивные (давно не менялись) — dim;
↘ inbox — свежее (до 7 дней) и то, что непонятно куда;
↙ trash — Корзина.

1. status → scan → wallpaper_map. Непонятное — peek.
2. Каждый элемент — ровно в одно место: группа или вне стола
   (move_to_folder в папку проекта / quarantine).
3. В карантин — только очевидный мусор: точные дубли (одинаковый хеш), установщики уже
   установленных программ, логи и временные файлы, битые ярлыки, ярлыки-дубли панели задач,
   ярлыки, которые не запускались больше полугода. Работы пользователя (psd, исходники,
   конфиги, проекты) — никогда в карантин, только в папки или во входящие.
4. Не трогай файлы своими инструментами (shell, PowerShell) — только через propose_plan.
5. После propose_plan коротко (5–10 строк) скажи, что куда и почему, отдельно — что уходит
   в карантин. Попроси зажать Ctrl+Alt для превью и вызови wait_for_decision.
6. Правки пользователя — новым propose_plan (старый заменится).
```
